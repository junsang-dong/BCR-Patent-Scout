# 실제 AI 연결 품질 확인 (2026-10-10)

> 실행: `node scripts/quality.mjs http://localhost:5173` · 공급자 `anthropic` / 모델 `claude-sonnet-5-5` · KIPRIS는 실제 호출
> 대상: A200 일체형 관절 조사에서 요약 키워드 겹침이 큰 특허 6건 (감속기·엔코더·브레이크·일체형 구조 4개 요소). 6건은 사람이 고른 것이 아니라 키워드 겹침 순위로 자동 선택했다.
> OpenAI는 `OPENAI_MODEL`이 비어 있어 시험하지 않았다.

## 결과

| 항목 | 결과 |
|---|---|
| 근거 문장 검증 | **17/17** 원문에 실재 (match·partial 칸 전부) |
| 유사성 평가 시간 | 5건 한 번에 **97초 → 프롬프트 다듬은 뒤 89초.** 출력 토큰이 6천~8천이라 느림 |
| 평가 토큰 (6건) | 입력 약 1만 2천 · 출력 약 1만 |
| 보고서(연구개발형) | 34초, 경고 0건, 머리말 7항목, 첫 줄 "AI 초안 — 검토 전" |
| 판정 | 근거가 없는 요소는 `없음`으로 두고(예: 브레이크 없음), 감속기 종류·엔코더 분해능 같은 차이를 구체적으로 짚음 |

## 확인된 문제와 조치

| 문제 | 조치 | 상태 |
|---|---|---|
| AI가 만든 JSON 문자열에 오류가 있어 서버가 500으로 종료 (재시도 경로를 타지 않음) | JSON 파싱 실패도 "오류 내용을 붙여 한 번 재요청"하도록 고침. 프롬프트에 큰따옴표 규칙 추가 | 수정, 이후 재현 안 됨 |
| 브레이크 캘리퍼(관절 모듈이 아님)를 종합 `보통`으로 평가 | 대상 제품 종류가 다르면 `low`로 하도록 프롬프트에 규칙 추가 | 수정, 재시험에서 `low`·근거 0건 |
| 보고서 본문에 입력 필드 이름이 새어 나옴 ("reviewed: false") | 보고서 프롬프트에 필드명 사용 금지 추가 | 수정 (재생성 확인은 안 함) |
| 5건 평가가 약 90초 (Vercel 기본 한도 근처) | 화면의 평가 묶음을 5건 → **3건**으로 줄이고, `analyze-similarity` 함수 한도를 90초 → 180초로 올림 | 조치, Vercel에서는 미측정 |
| 차이점 문장이 길고 중복 | 차이점 최대 3개·80자, 질문 최대 2개·60자 제한 | 수정, 항목 수는 지켜짐 |

## 아직 모르는 것
- 사람(연구개발팀) 기준의 판정 정확도. 이 확인은 근거 문장이 원문에 있는지(검증 통과)와 읽어 본 인상이다. 판정이 맞는지는 전문가가 봐야 한다.
- 6건 표본이라 일반화할 수 없다. 특히 `partial` 판정이 후한 경우가 있어 보인다 (예: 파동 발생기가 구동축과 일체형이라는 문장을 "일체형 관절"의 부분 일치로 봄).
- 명세서 본문·도면은 입력에 없다. 청구항도 앞 3개만 쓴다.
- 비용: 위 토큰 수만 기록했고 금액은 계산하지 않았다.
