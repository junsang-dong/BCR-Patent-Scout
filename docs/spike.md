# M0 Spike 기록 (명세 10.2)

> 실측일 2026-10-10 · 실제 KIPRIS 키로 로컬 개발자 PC(macOS)에서 측정 · 실행: `node scripts/spike.mjs`, `node scripts/spike-followup.mjs`
> 이 키는 "특허·실용 공개·등록공보", "법적 상태 이력", "등록사항" 상품 신청이 승인된 뒤에야 통했습니다. 신청 전에는 `오류 31 DEADLINE_HAS_EXPIRED_ERROR`(인증)였습니다.
> 호출은 약 40회(스파이크 22 + 후속 15 + 앱 흐름 시험)이며 키 값은 어디에도 출력하지 않았습니다.

## 결과 요약

| # | 확인 항목 | 결과 | 상태 |

## 실측이 바꾼 것

1. **기본 검색식이 너무 좁았다.** 제목 `관절` + 요약 + IPC를 모두 걸면 7개 요소 중 4개가 0~2건이었다 (예: 파동기어+F16H → 0건, 브레이크+F16D → 1건). 제목 키워드를 기본에서 빼고 요약+IPC로 찾도록 바꿨다 (`shared/queries.js`). IPC 후보가 없는 요소만 제목을 유지한다. 화면에 "제목에도 대표어 넣기" 선택을 둠.
2. 기간을 받은 뒤 거르던 방식을 서버 필터(`applicationDate`)로 바꿨다. 받은 뒤 거르기는 안전장치로 남김.
3. `KIPRIS_SCHEME` 기본값을 `https`로.
4. 파서가 **실제 응답으로 검증됐다**: 검색 5건의 출원번호·출원일·명칭·출원인·IPC·상태가 정상 파싱, 서지 상세(삼성전자 1020130119441)는 제목·상태·IPC·청구항(삭제 청구항 포함 20개)·출원인이 정상. 패밀리 정보는 0건으로 나옴(이 특허에는 없는 것으로 보임).

## 같은 실측으로 본 AT-2 (건수 과다)

앱의 `a200-brake`(요약 브레이크 + IPC F16D, 2016~2026)가 **1,893건**이라 수집은 200건에서 멈추고 "잘림"으로 표시되었다. 이 검색식은 `B25J 19` 등으로 더 좁히거나 제목 대표어를 켜야 한다. (제목 `관절`까지 걸면 1건.) 적정 범위는 그 사이이므로 연구개발팀이 키워드·IPC를 보정해야 한다.
